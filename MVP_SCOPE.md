# MVP Scope v0.1

## 1. Цель MVP
Сделать первый рабочий релиз сервиса аудита лифтовой документации для УК: от загрузки документов до отчета и выставления счета.

Комментарий: основной фокус MVP не в максимальном функционале, а в коротком замкнутом контуре ценности для клиента и команды.

## 2. Что точно делаем сейчас (In Scope)
1. Публичный сайт с описанием услуги и кнопкой входа в ЛК.
2. Личный кабинет с регистрацией и входом.
3. Роли и права: `UK_USER`, `AUDITOR`, `ADMIN`.
4. Формирование аудита по выборке `3-5 лифтов` на одну УК (бизнес-правило MVP).
5. Загрузка документов по лифту с телефона/ПК.
6. Лимиты загрузки: до `3 МБ` на файл, суммарно до `180 МБ` на один аудит.
7. Запуск фоновой проверки документов через очередь задач.
8. Полностью автоматизированный анализ и осмотр через OCR/распознавание.
9. Проверка по топ-5 критериям чек-листа (первый релиз движка).
10. Отчет по лифту со статусами `OK`, `NOT_OK`, `NO_DATA`.
11. Финальный отчет только в форматах: web-форма в ЛК + PDF.
12. Выставление счета, акта и базовая интеграция с 1С.
13. Деплой на текущий сервер через `docker compose` + `nginx`.
14. Health-check и минимальные автотесты на критичные API-ручки.

Комментарий: этот набор уже покрывает основной путь клиента и дает возможность быстро продавать услугу.

## 3. Что не делаем сейчас (Out of Scope)
1. Глубокая двусторонняя интеграция с 1С по всем сущностям и справочникам.
2. Полная автоматизация всех 19 критериев проверки.
3. Продвинутый CRM, BI-аналитика и сложная телефония.
4. Мультиарендность с изоляцией по отдельным БД.
5. Сложные AI-фичи вне предметного чек-листа.

Комментарий: эти пункты отложены, чтобы сократить время до первого стабильного запуска.

## 4. Роли и права (RBAC)
1. `UK_USER`:
- создает и редактирует свои лифты;
- загружает документы;
- смотрит только данные своей компании;
- видит отчеты и счета своей компании.
2. `AUDITOR`:
- видит назначенные аудиты;
- добавляет комментарии и финализирует проверку;
- не управляет пользователями и биллингом системы.
3. `ADMIN`:
- управляет пользователями и ролями;
- видит все компании, аудиты, отчеты и счета;
- изменяет системные справочники и настройки.

Комментарий: минимальный RBAC снижает риск утечки данных между УК.

## 5. Данные и сущности MVP
1. `companies`.
2. `users`.
3. `lifts`.
4. `documents`.
5. `audit_jobs`.
6. `audit_results`.
7. `invoices`.
8. `payments`.

Комментарий: этого достаточно для полного бизнес-цикла: клиент -> проверка -> результат -> счет -> оплата.

## 6. Проверки: топ-5 критериев для релиза 1
1. Назначение специалиста, ответственного за ТО и Р лифта.
2. Назначение ответственного электромеханика.
3. Наличие результатов периодического технического осмотра.
4. Наличие квалификационного удостоверения у специалиста, ответственного за безопасную эксплуатацию лифтов.
5. Наличие организационно-распорядительных документов о назначении ответственных за безопасную эксплуатацию, ТО и ремонт лифтов.

Комментарий: выбираем критерии, по которым быстрее всего получить понятный и проверяемый результат.

## 7. Формат отчета в ЛК
1. Раздел "Сводка":
- количество критериев `OK`;
- количество критериев `NOT_OK`;
- количество критериев `NO_DATA`;
- список критичных несоответствий.
2. Раздел "Детализация": для каждого критерия:
- `status`;
- `reason`;
- `evidence` (какой файл/страница);
- `recommendation`.
3. Финальный отчет доступен только в web-версии и PDF.

Комментарий: клиент должен видеть не только вердикт, но и объяснение, что исправлять.

## 8. Инфраструктура и деплой MVP
1. Сервисы: `frontend`, `backend`, `worker`, `redis`, `nginx`.
2. PostgreSQL не поднимается в compose, используется внешний сервер по IP и паролю.
3. Конфигурация хранится в `.env` (секреты не коммитим).
4. Nginx маршрутизирует:
- `/` -> frontend;
- `/api/*` -> backend.
5. Политика хранения документов:
- исходные файлы хранятся временно до формирования финального отчета;
- после формирования отчета исходники автоматически удаляются через 30 дней или переводятся в архив (по настройке проекта).
6. Резервные копии: отдельный cron-скрипт с выгрузкой БД.

Комментарий: такая схема проста для запуска и не мешает масштабированию дальше.

## 9. Минимальный Definition of Done
1. Регистрация/логин работает.
2. Пользователь УК создает аудит по выборке 3-5 лифтов и загружает документы.
3. OCR-пайплайн полностью автоматически формирует результат проверки.
4. Отчет отображается в ЛК и доступен в PDF.
5. Счет и акт создаются и передаются в 1С (минимальный контур MVP).
6. `/api/health` отдает `ok`.
7. Есть минимум smoke-тесты API.

Комментарий: DoD фиксирует, что именно считается завершенной разработкой для MVP.
